# MediaHub — автономный медиа-хаб и конвертер

![Демонстрация](docs-demo.gif)

Локальный веб-инструмент «швейцарский нож» для конвертации, оптимизации и передачи
медиафайлов. Вся обработка выполняется на вашей машине: файлы не уходят на внешние
серверы, нет рекламы и ограничений по размеру, нет платных API.

Реализованы **Этапы 1–3** технического задания (хранилище и сборщик мусора, сервисы
трансформации, REST API), интерфейс в объёме раздела 5 ТЗ и упаковка по Этапу 5
([`Dockerfile`](Dockerfile)).

```
Изображения  JPG · PNG · WEBP · HEIC/HEIF · BMP · TIFF · AVIF
Документы    склейка PDF · сжатие PDF · PDF в картинки
Медиа        извлечение MP3 · оптимизированный GIF · сжатие видео H.264
Мобильный    QR-код со ссылкой на результат для телефона в той же сети Wi-Fi
```

## 1. Быстрый старт

### Windows

```bat
start.cmd                     :: сам поставит зависимости и запустит сервер
start.cmd --check             :: только проверка окружения
```

### Linux / macOS

```sh
./start.sh
./start.sh --check
```

### Вручную (любая платформа)

```sh
python -m pip install -r requirements.txt
python -m mediahub                      # http://127.0.0.1:8765
python -m mediahub --port 9000           # другой порт
python -m mediahub --check               # отчёт о зависимостях
```

Если глобальный `site-packages` недоступен для записи, установите зависимости
в каталог проекта — сервер и тесты подхватят их автоматически:

```sh
python tools/bootstrap.py          # ставит пакеты в ./.piptarget
python tools/bootstrap.py --venv   # либо создаёт ./.venv
```

### FFmpeg (для видео и аудио)

Модуль медиа требует системный `ffmpeg`. Он ищется в `PATH`, затем в каталоге
`vendor/ffmpeg`. Без него сервер **не падает**: эндпоинты видео/аудио возвращают
`503` с инструкцией по установке.

```sh
# без прав администратора — скачает сборку в vendor/ffmpeg
python tools/install_ffmpeg.py

# либо системно
winget install --id Gyan.FFmpeg -e     # Windows
brew install ffmpeg                    # macOS
sudo apt-get install -y ffmpeg         # Debian / Ubuntu
```

### HEIC/HEIF (снимки iPhone)

Чтение HEIC обеспечивает необязательная библиотека `pillow-heif`; она входит в
`requirements.txt`, поэтому ставится вместе с остальными зависимостями:

```sh
python -m pip install pillow-heif
```

Без неё сервер работает, но HEIC-файлы отклоняются с кодом 422 и подсказкой.
Ориентацию таких снимков библиотека применяет при чтении сама.

### Docker

```sh
docker build -t mediahub .
docker run --rm -p 8765:8765 -v mediahub-storage:/app/storage mediahub
```

### Постоянный запуск (автозагрузка)

**Windows** — задача планировщика, стартующая при входе в систему. Прав
администратора не требуется:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\install-windows-service.ps1 install
powershell -ExecutionPolicy Bypass -File deploy\install-windows-service.ps1 install -DryRun   # только показать, что будет сделано
powershell -ExecutionPolicy Bypass -File deploy\install-windows-service.ps1 status
powershell -ExecutionPolicy Bypass -File deploy\install-windows-service.ps1 uninstall
```

Логи пишутся в `storage/logs/mediahub.out.log` и `.err.log`. Если автоматика выбрала
не тот интерпретатор, задайте его явно: `set MEDIAHUB_PYTHON=C:\Python312\python.exe`.

**Linux** — готовый systemd-юнит [`deploy/mediahub.service`](deploy/mediahub.service):

```sh
sudo cp deploy/mediahub.service /etc/systemd/system/mediahub.service
sudo systemctl daemon-reload && sudo systemctl enable --now mediahub
systemctl status mediahub && journalctl -u mediahub -f
```

Юнит запускает сервер не от root, ограничивает запись каталогом хранилища и
перезапускает процесс при сбое.

## 2. Как пользоваться

1. Откройте <http://127.0.0.1:8765> — откроется интерфейс.
   Быстрый показ без перетаскивания файлов: <http://127.0.0.1:8765/?demo=1>
   подставит пример изображения и даст сразу нажать «Обработать».
2. Перетащите файлы в зону приёма (или выберите на диске). Инспектор типов не даст
   смешать изображения, PDF и видео в одном запросе.
3. Панель настроек подстроится под тип данных:
   * **картинки** — целевой формат (JPG/PNG/WEBP) и ползунок качества 10–100 %;
   * **один PDF** — «Сжать размер» либо «Экспортировать страницы как картинки» (150/200 DPI);
   * **несколько PDF** — карточки файлов с перетаскиванием для порядка склейки;
   * **видео** — «Только звук (MP3)», «Превратить в GIF», «Сжать видео».
4. Нажмите «Обработать»: кнопка блокируется, показывается прогресс и текстовый статус.
5. В карточке результата — сравнение размеров («Было → Стало, экономия N %»), кнопка
   скачивания, кнопка **«Передать на телефон»** с крупным QR-кодом и сброс одним нажатием.

> Смартфон должен быть в той же сети Wi-Fi. Сервер подставляет в QR-код свой
> LAN-адрес (`192.168.x.x` / `10.x.x.x`), а не `127.0.0.1`, поэтому ссылка
> открывается с телефона. Если автоматика ошиблась, задайте адрес вручную:
> `MEDIAHUB_PUBLIC_HOST=192.168.1.50`.

## 3. Жизненный цикл сессий и дисковое пространство (ТЗ 2)

* На каждый запрос создаётся **Task ID** формата UUIDv4 — единственный источник имён
  на диске. Клиентские имена только санитизируются и никогда не участвуют в путях.
* Внутри `<storage>/<task_id>/` создаются `raw/` (входящие файлы) и `out/` (результаты).
* **TTL 30 минут**: демон каждые 5 минут рекурсивно удаляет устаревшие сессии.
* **Однократное использование** (по умолчанию выключено, `MEDIAHUB_BURN_AFTER_DOWNLOAD=true`):
  после полной выдачи файла сессия уничтожается через 60 секунд.
* При любой ошибке сессия удаляется немедленно, не дожидаясь демона.

Настройки: `MEDIAHUB_TASK_TTL`, `MEDIAHUB_GC_INTERVAL`, `MEDIAHUB_BURN_AFTER_DOWNLOAD`,
`MEDIAHUB_BURN_DELAY`, `MEDIAHUB_STORAGE_DIR`.

## 4. REST API (ТЗ 3)

Полная интерактивная документация — <http://127.0.0.1:8765/api/docs>.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/health` | состояние сервера, хранилища, FFmpeg и лимитов |
| `GET` | `/api/network` | LAN-адрес, порт, базовый URL для QR |
| `POST` | `/api/convert` | загрузка файлов и постановка задачи (202) |
| `GET` | `/api/jobs/{job_id}` | статус, прогресс, метрики результата |
| `DELETE` | `/api/jobs/{job_id}` | отмена задачи и удаление сессии |
| `DELETE` | `/api/tasks/{task_id}` | удаление сессии вручную |
| `GET` | `/download/{task_id}` | результат целиком (файл или ZIP) |
| `GET` | `/download/{task_id}/{name}` | конкретный файл из набора |
| `GET` | `/qr/{task_id}` | PNG с QR-кодом ссылки для телефона |

### Параметры `POST /api/convert` (multipart/form-data)

| Поле | Значения |
|---|---|
| `kind` | `image` · `pdf` · `video` |
| `action` | image: `convert` (по умолчанию) · pdf: `merge` · `compress` · `to_images` · video: `mp3` · `gif` · `compress` |
| `format` | `jpg` · `png` · `webp` (изображения и рендер PDF) |
| `quality` | 1–100 (изображения), 10–95 (сжатие PDF) |
| `dpi` | `150` · `200` (PDF → картинки) |
| `bitrate` | `128` · `192` · `256` · `320` kbps (MP3) |
| `fps`, `width`, `seconds`, `start` | параметры GIF |
| `crf` | 18–35 (сжатие видео, по умолчанию 27) |
| `files` | сами файлы; имя поля любое, кроме служебных |
| `max_files`, `max_bytes` | необязательное понижение лимитов внутри запроса |

### Пример: конвертация изображений

```sh
curl -X POST http://127.0.0.1:8765/api/convert \
     -F kind=image -F format=jpg -F quality=70 \
     -F files=@photo1.png -F files=@photo2.png
```

```json
{
  "job_id": "0f6c…", "task_id": "1b2a…", "status": "queued",
  "download_url": "/download/1b2a…", "qr_url": "/qr/1b2a…"
}
```

```sh
curl http://127.0.0.1:8765/api/jobs/0f6c…     # опрос статуса
curl -OJ http://127.0.0.1:8765/download/1b2a… # скачивание результата
```

### Пример: склейка PDF в заданном порядке

Порядок склейки = порядок полей `files` в запросе.

```sh
curl -X POST http://127.0.0.1:8765/api/convert \
     -F kind=pdf -F action=merge \
     -F files=@cover.pdf -F files=@body.pdf -F files=@appendix.pdf
```

### Коды ошибок

| Код | Когда возникает |
|---|---|
| `400 invalid_request` | неизвестный тип или действие, нет файлов, параметр вне диапазона |
| `404 not_found` | задача или файл не найдены, результат уже удалён по TTL |
| `409 conflict` | результат ещё обрабатывается (в ответе есть `progress` и `status_url`) |
| `413 payload_too_large` | больше 50 файлов или тяжелее 200 МБ |
| `422 unprocessable_file` | подделанное расширение, битый или защищённый файл |
| `503 dependency_unavailable` | нет FFmpeg **или** найденный файл не запускается; в ответе — шаги установки |
| `504 processing_timeout` | FFmpeg превысил лимит 120 с и был уничтожен |

## 5. Алгоритмические детали реализации

**Изображения (Pillow).** Палитровые `mode P` принудительно приводятся к RGBA. Если у
исходника есть альфа-канал, а целевой формат — JPEG, картинка сводится на непрозрачный
белый холст `#FFFFFF` (`paste` с альфа-маской) — прозрачность не даёт ни ошибки, ни
чёрных пятен. EXIF-тег ориентации применяется физически (`ImageOps.exif_transpose`),
а в сохраняемых метаданных сбрасывается в `1`, чтобы вьюеры не развернули кадр дважды.
Для JPEG включается `optimize` и `progressive`, для WEBP — максимальный `method=6`,
для PNG — `compress_level=9`. Один файл → один результат, несколько → плоский ZIP.

**PDF (pypdf + pypdfium2).**
* *Склейка*: каждый файл проверяется по сигнатуре `%PDF-` и открывается pypdf; при
  ошибке пользователь получает имя конкретного проблемного файла. Закладки берутся
  только из первого документа — иначе ссылки конфликтуют. Максимум 20 файлов.
* *Сжатие*: обход встроенных `XObject Image` (без масок и inline-картинок), кадры
  перекодируются в JPEG до 35–65 % качества и заменяются только если стали меньше;
  затем `compress_identical_objects` сжимает потоки контента, удаляет дубликаты
  объектов и «осиротевшие» ссылки, метаданные редакторов стираются.
* *PDF → картинки*: рендер PDFium с масштабом `dpi / 72`, файлы `page_001.png`,
  `page_002.png`, … упаковываются в ZIP. Если `pypdfium2` недоступен, возвращается 503.

**Медиа (FFmpeg).**
* Наличие `ffmpeg` проверяется при старте и перед каждым вызовом (кэш поиска).
  Проверяется не только наличие файла, но и возможность запуска: повреждённая или
  несовместимая сборка даёт 503 с инструкцией, а не внутреннюю ошибку 500.
* MP3: `-vn -map 0:a:0`, libmp3lame, 44.1 кГц, битрейт пользователя.
* GIF: обрезка первых N секунд, `fps` 10–15, ширина 480 px с сохранением пропорций,
  двухпроходный фильтр `palettegen` → `paletteuse=dither=sierra2_4a`.
* Сжатие видео: libx264 `profile main`, `yuv420p`, CRF 26–28, AAC 128 kbps,
  `+faststart` для быстрого старта в мессенджерах.
* Каждый процесс запускается с жёстким лимитом времени; по истечении срока
  он уничтожается (`taskkill /F /T` → `kill()` → закрытие каналов) и клиент
  получает 504. Прогресс читается отдельным потоком, поэтому таймаут не блокируется.

**Состояния гонки и ресурсы.** Обращение к результату, пока задача ещё считается
выполняющейся, возвращает 409 с текущим прогрессом — это не «файл удалён».
Реестр завершённых задач чистится по расписанию (раз в 30 минут), иначе он рос бы
бесконечно; сама сессия на диске живёт по TTL независимо от реестра.

## 6. Безопасность

* **Path traversal**: имена на диске генерируются сервером (UUID + санитизация),
  каждый путь проверяется на принадлежность каталогу сессии.
* **Magic bytes**: Pillow и pypdf валидируют содержимое — `.exe`, переименованный в
  `.jpg`, отсекается кодом 422 ещё до конвертации.
* **Локальный доступ**: запросы принимаются только с loopback и приватных адресов.
  Исключение — явный `MEDIAHUB_ALLOW_PUBLIC=true`.
* **Токен**: если задан `MEDIAHUB_TOKEN`, он обязателен в заголовке
  `X-MediaHub-Token` (или в параметре `token`).
* **Таймауты и очистка**: см. раздел 5; временные сессии удаляются даже при сбое.

## 7. Проверка

### 7.1. Автотесты (без браузера)

```sh
python -m pytest              # 166 тестов: хранилище, сервисы, API, выдача файлов
python -m pytest -k pdf       # только PDF
```

Тесты, требующие настоящего FFmpeg, автоматически пропускаются, если его нет;
проверка деградации до 503 при этом выполняется всегда.

```
tests/test_stage1_storage.py   сессии, TTL-GC, path traversal, санитизация имён
tests/test_stage2_images.py    альфа-канал, палитра, EXIF-ориентация, качество
tests/test_stage2_pdf.py       склейка, сжатие, рендер страниц
tests/test_stage2_media.py     pre-flight 503, таймаут, классификация ошибок
tests/test_stage3_api.py       сеть, QR-мост, сквозные сценарии REST API, интерфейс
```

### 7.2. Приёмочная самопроверка на реальных файлах

```sh
python tools/make_fixtures.py          # создать набор тестовых файлов в ./.fixtures
python tools/selftest.py --deep        # прогнать полный сценарий и напечатать отчёт
python tools/selftest.py --url http://127.0.0.1:8765 --deep   # то же, но по живому HTTP
```

Проверяются не только коды ответов, но и содержимое результата: магия `%PDF-`,
размеры страниц после склейки, физический разворот пикселей по EXIF, сведение
альфы на белый холст, соотношение рендеров 200/150 DPI, а с флагом `--deep` —
кодеки и длительность через FFprobe (`h264` + `aac`, `+faststart`, кадры GIF).

### 7.3. Логика интерфейса

```sh
node verify/ui_logic_test.mjs
```

Поднимает минимальный DOM-шим, загружает настоящий `web/app.js` и проверяет
инспектор типов, блокировку смешения, лимиты, построение панели настроек,
ползунок качества и сборку параметров запроса для всех режимов.

### 7.4. Интерфейс в браузере (скриншоты)

```sh
python -m mediahub --port 8765 &        # запущенный сервер
python verify/demo_shots.py --out _shots   # полный сценарий + скриншоты
python verify/ui_driver.py --url http://127.0.0.1:8765 --out _shots
```

`demo_shots.py` открывает страницу с демо-файлом, переключает форматы, запускает
обработку, дожидается карточки результата, открывает QR-окно и снимает мобильную
вёрстку. `ui_driver.py` дополнительно проверяет состояния интерфейса (заблокированная
кнопка, прогресс, заблокированное смешение типов) и оставляет снимки каждого шага.

> Chrome нельзя запустить внутри изолированной среды DSH: песочница запрещает
> именованные каналы, которые Chrome использует для IPC
> (`FATAL: platform_channel.cc: Access denied`). Поэтому драйвер рассчитан на
> обычный запуск из терминала.

### 7.5. Dockerfile без Docker

```sh
python verify/dockerfile_check.py
```

Статически проверяет Dockerfile: синтаксис инструкций, установку FFmpeg и шрифтов,
наличие всех `COPY`-источников, запуск не от root, `HEALTHCHECK` и чистоту
контекста сборки (`dockerignore`). Сборка образа при этом не выполняется.

### 7.6. Скрипты развёртывания

```sh
python verify/deploy_check.py
```

Проверяет PowerShell-скрипт постоянного запуска (в том числе настоящим парсером
PowerShell и наличие BOM: без него PowerShell 5.1 ломает кириллицу) и systemd-юнит
(секции, ограничения, согласованность путей хранилища).

### Что осознанно вынесено за рамки текущей итерации

* HEIC/HEIF работает через необязательную библиотеку `pillow-heif`
  (`pip install pillow-heif`, она же включена в `requirements.txt`). Ориентацию
  таких снимков применяет сама библиотека при чтении и сбрасывает EXIF-тег, поэтому
  наш шаг разворота для них безвреден и не переворачивает кадр дважды — это
  закреплено отдельным тестом. Если библиотека не установлена, файл отклоняется
  с кодом 422 и понятным пояснением.
* Интерфейс — минимальный SPA без сборщика: компонентная структура реализована
  функциями отрисовки в `web/app.js`. Переход на фреймворк не меняет контракт API.

## Портативная сборка

Один файл без Python и зависимостей:

```bash
pip install pyinstaller
python tools/build_exe.py
```

Результат – `dist/MediaHub.exe`. Скрипт включает веб-интерфейс и HEIC-плагин
внутрь сборки.
